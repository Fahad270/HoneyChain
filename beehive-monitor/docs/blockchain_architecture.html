The 9-Stage Honey Journey & DAG Batch Convergence

Each stage represents a verifiable hop. Linear hops link via prev_hash. When KVIC centers pool honey from multiple farmers, a Convergent Directed Acyclic Graph (DAG) merges multiple parent hashes into a single lot hash.

01 🐝
Beekeeper Registration (Genesis Block) Actor: Beekeeper
Farmer enrolled with Aadhaar Verhoeff KYC verification. System auto-mints genesis block with prev_hash = null.
hash = SHA256(null | "beekeeper_registration" | canonical({ beekeeperId, village, aadhaarHash }))
02 🍯
Honey Extraction Actor: Beekeeper
Honey harvested at apiary. Records hive ID, extraction weight (kg), floral nectar source, and moisture estimate.
hash = SHA256(genesisHash | "honey_extraction" | canonical({ hive_id, weight_kg, flower_source }))
03 🔗
Collection & Pooled Convergence (DAG Merge) Actor: KVIC Field Officer / Cooperative
Convergent DAG: Multiple farmer extraction hashes [H1, H2, H3, ... HN] are aggregated into a single cooperative bulk lot. Preserves individual farmer provenance.
pooledHash = SHA256(sorted([H1, H2, H3, ...]).join("|") | "pooled" | canonical({ collective_name, total_weight_kg }))
04 🚚
Bulk Transport Actor: Transporter / Logistics
Truck shipment from village cluster collection point to central KVIC processing plant. Logs vehicle number, transit temperature, dispatch timestamp.
hash = SHA256(pooledHash | "transport" | canonical({ truck_no, origin_cluster, destination_facility }))
05 🧪
Processing & Quality Assurance Actor: Processing Facility QA
Controlled heating (≤45°C to preserve diastase/enzymes), double filtration, settling. QA officer signs off filtration and purity checks.
hash = SHA256(transportHash | "processing" | canonical({ filtered: true, pasteurized: false, qa_officer }))
5B 🔬
Accredited Laboratory Certification Actor: KVIC / NABL Testing Lab
Chemical & isotopic profiling: moisture ≤ 20%, C3/C4 sugar syrup adulteration tests, HMF activity, Agmark / FSSAI CA certification hash.
hash = SHA256(processingHash | "lab_certified" | canonical({ ca_number, moisture: "18.2%", cert_hash }))
06 🏷️
Packaging & Labeling (Jar QR Minting) Actor: Packaging Unit
Bottling in food-grade glass jars. Unique jarSerial generated (e.g. JAR-9A4B-3C2D). Jar QR code is printed with the block hash as the Public Key.
hash = SHA256(labHash | "packaging" | canonical({ jar_serial: "JAR-...", batch_size }))
07 📦
Distribution Actor: Distributor
Dispatch manifest assigning specific jar lots to designated Khadi Bhavan and KVIC retail outlets across Indian cities.
hash = SHA256(packagingHash | "distribution" | canonical({ dest_store: "Khadi Bhavan Connaught Place", city }))
08 🔒
Retail Sale & Cryptographic Freeze (is_frozen = true) Actor: Khadi Retail POS
Chain Freeze: POS cashier logs sale bill. The ledger marks is_frozen = true; any subsequent attempt to append child blocks is rejected. Generates single-use Bill Private Key.
hash = SHA256(distHash | "retail" | canonical({ store_name, bill_no, is_frozen: true }))
09 ✅
Consumer Dual-Key Authentication Actor: Buyer / Consumer
Consumer scans Jar QR (Public Key) + enters Bill Secret (Private Key). Smart contract verifies commitment match and ensures this is the 1st valid verification.
commitment = SHA256(privateKey.toLowerCase() | publicKey | registryKey) == jar.privateKeyCommit

Solving the QR Code Cloning Vulnerability: Dual-Key Cryptography

Standard blockchain supply chains rely on simple static QR codes on packaging. Counterfeiters exploit this by purchasing one genuine jar, photocopying its QR code onto 1,000 bottles of cheap rice syrup, and selling them. HoneyChain eliminates this vulnerability through an asymmetric commitment scheme.

❌ The Vulnerability: Static QR Cloning

When a consumer scans a standard QR code, they see a valid blockchain explorer with genuine lab reports. However, the system cannot distinguish between the authentic jar and 999 cloned bottles sporting the identical printed QR code.

Photocopied Jar #1 --> Scans Genuine QR --> Ledger says "Authentic!" ❌ Photocopied Jar #2 --> Scans Genuine QR --> Ledger says "Authentic!" ❌ Photocopied Jar #999--> Scans Genuine QR --> Ledger says "Authentic!" ❌

Result: Counterfeit honey is legitimized by a genuine blockchain record.

🛡️ HoneyChain Solution: Dual-Key Commitment

HoneyChain splits proof of authenticity across two separate channels that only converge in the hands of the legitimate buyer:

  • Public Key (Jar QR): Embedded on physical label. Anyone can scan to inspect the public supply chain journey.
  • Private Key (Bill Voucher): Generated randomly by the POS at the moment of billing (e.g. HC-9F2A-4B8C-1E5D) and printed exclusively on the cashier paper bill.
  • Cryptographic Commitment: The hash commitment keccak256(privateKey) is anchored in the contract upon sale.

Verification Scenarios Handled by HoneyChain

Scenario A: Public Browse

User scans jar on shelf without buying. Can view farmer & lab history, but authenticity verdict remains "Unsold / Unclaimed".

Scenario B: Genuine Buyer (1st Claim)

Buyer enters bill code. Commitment matches. Status: Authentic First Claim. Timestamp recorded.

Scenario C: Fraudulent 2nd Scan

Counterfeiter attempts to verify a second jar using the same code. Status: Duplicate Claim Scam Alert with exact time of first claim.

HoneyChainRegistry.sol (EVM Smart Contract)

Solidity contract compiled with ^0.8.20 for deployment on EVM-compatible networks (Polygon POS, Arbitrum, or private Hyperledger Besu consortium).

// SPDX-License-Identifier: MIT pragma solidity ^0.8.20; contract HoneyChainRegistry { address public owner; bytes32 public registryKey; struct Batch { bytes32 publicKey; // SHA256 of packaging block string ipfsCid; // Immutable Pinata IPFS Content Identifier bytes32 prevHash; // Previous block hash in DAG string stage; // Stage name (e.g., "packaging") string jarSerial; // Unique Jar Serial (e.g., "JAR-9A4B-3C2D") bool exists; bool sold; bytes32 purchaseCommit; // keccak256(privateKey) issued upon retail sale uint256 verifyCount; // Number of times verified (flags duplicates) uint256 anchoredAt; // Block timestamp } mapping(bytes32 => Batch) public batches; mapping(string => bytes32) public serialToPublicKey; mapping(bytes32 => bool) public usedCommits; event RegistryKeyIssued(bytes32 indexed key, address indexed deployer); event Anchored(bytes32 indexed publicKey, string cid, string stage, string jarSerial); event PurchaseIssued(bytes32 indexed publicKey, bytes32 commit, string billNo); event DualVerified(bytes32 indexed publicKey, bool ok, string reason, uint256 verifyCount); modifier onlyOwner() { require(msg.sender == owner, "not owner"); _; } constructor() { owner = msg.sender; registryKey = keccak256( abi.encodePacked(block.timestamp, msg.sender, block.prevrandao, address(this)) ); emit RegistryKeyIssued(registryKey, msg.sender); } /// Anchors IPFS CID and batch hash onto the immutable ledger function anchor( bytes32 publicKey, string calldata ipfsCid, bytes32 prevHash, string calldata stage, string calldata jarSerial ) external onlyOwner { require(publicKey != bytes32(0), "empty key"); require(bytes(ipfsCid).length > 0, "empty cid"); Batch storage b = batches[publicKey]; require(!b.exists, "already anchored"); if (bytes(jarSerial).length > 0) { require(serialToPublicKey[jarSerial] == bytes32(0), "duplicate jar serial"); serialToPublicKey[jarSerial] = publicKey; } batches[publicKey] = Batch({ publicKey: publicKey, ipfsCid: ipfsCid, prevHash: prevHash, stage: stage, jarSerial: jarSerial, exists: true, sold: false, purchaseCommit: bytes32(0), verifyCount: 0, anchoredAt: block.timestamp }); emit Anchored(publicKey, ipfsCid, stage, jarSerial); } /// Cashier POS commits purchase at retail sale function issuePurchase(bytes32 publicKey, bytes32 commit, string calldata billNo) external onlyOwner { Batch storage b = batches[publicKey]; require(b.exists, "unknown jar"); require(!b.sold, "already sold"); require(commit != bytes32(0), "empty commit"); require(!usedCommits[commit], "commit reused"); b.sold = true; b.purchaseCommit = commit; usedCommits[commit] = true; emit PurchaseIssued(publicKey, commit, billNo); } /// Dual-key verify: publicKey from QR + keccak256(privateKey) from bill. function verify(bytes32 publicKey, bytes32 commit) external returns (bool ok, string memory reason) { Batch storage b = batches[publicKey]; if (!b.exists) return _emitVerify(publicKey, false, "unknown public key"); if (!b.sold) return _emitVerify(publicKey, false, "not sold - bill code not issued"); if (b.purchaseCommit != commit) return _emitVerify(publicKey, false, "private key mismatch"); b.verifyCount += 1; if (b.verifyCount > 1) { return _emitVerify(publicKey, false, "duplicate claim - this jar was already verified"); } return _emitVerify(publicKey, true, "authentic first claim"); } function _emitVerify(bytes32 publicKey, bool ok, string memory reason) internal returns (bool, string memory) { emit DualVerified(publicKey, ok, reason, batches[publicKey].verifyCount); return (ok, reason); } }

Cryptographic Schema & Data Contracts

Structure of the LedgerBlock and JarRecord entities in the MongoDB collection and local runtime cache.

LedgerBlock (Mongoose Schema)

{ hash: String, // SHA256 canonical hash (Indexed, Unique) prev_hash: String, // Parent hash for linear stages prev_hashes: [String], // Parent hashes array for "pooled" DAG stage: Enum(10), // "beekeeper_registration" ... "retail" data: Mixed, // Stage-specific JSON payload beekeeper: ObjectId, // Beekeeper reference scan_secret: String, // 16-hex char scan guard token is_frozen: Boolean, // Locks chain at stage "retail" ipfsCid: String, // Pinata CID (bafy...) publicKey: String, // Anchoring public key jarSerial: String, // Unique retail jar serial number createdBy: { userId: ObjectId, role: "beekeeper" | "kvic", centreId: String } }

JarRecord (Retail Anti-Cloning Unit)

{ jarSerial: String, // "JAR-XXXX-XXXX" (Indexed, Unique) hash: String, // Packaging block hash publicKey: String, // QR Public Key sold: Boolean, // True once POS logs sale billNo: String, // Retail cashier receipt number privateKeyCommit: String, // sha256(privateKey | pubKey | registryKey) verifyCount: Number, // Scan verification counter duplicateFlag: Boolean, // Set to true if verifyCount > 1 duplicateScans: [Date], // Audit timestamps of fraudulent scans firstVerifiedAt: Date, // Timestamp of first authentic claim lastVerifiedAt: Date }
